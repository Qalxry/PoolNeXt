## 2. 产品边界

### 2.1 本次完成

- 单主机、单 PoolNeXt 服务、单受管 Mihomo 进程、多监听入口。
- 数据库仍是配置真相源，正式 WebUI 不直接依赖 Mihomo 私有状态作为配置来源。
- zashboard 继续作为独立高级诊断界面，不并入 Next.js 组件树。
- 对新连接和连接建立失败，使用健康状态与 Mihomo `fallback` 尽力切换节点。
- 指定 Mihomo 文件只执行、查询版本或读取状态，不下载覆盖、不改权限、不移动。

### 2.2 明确不承诺

- 不透明重放已经开始传输的 HTTP 请求或 TCP 流。
- 不把 HTTP 429、业务 5xx 或非幂等请求失败自动重放到其他出口。
- 不在本 Goal 内实现多 Mihomo 实例、分布式 Agent、计费、多租户或复杂规则 DSL。
- 不以 24 小时 soak、10 万节点、完整 PostgreSQL/Docker/发布矩阵作为本次完成门槛。

## 3. 已交付功能

### 3.1 紧凑 WebUI

- 节点页改为无传统分页的紧凑表格，一次展示最多 1000 个节点。
- 支持关键词、启用状态和健康状态筛选，支持手动与 15 秒自动刷新。
- 支持多选、批量探测、批量启停、批量标签和批量删除。
- 提供全量节点巡检入口及健康、失败、未知、隔离汇总。
- 工作台节点选择器无分页，已选节点置顶；上下调整顺序即 `fallback` 优先级。
- 新建端口配置默认采用 `fallback`，并明确显示故障切换语义。
- 运行页集中展示进程、API 健康、自启、监听和运行配置状态。
- 日志页提供结构化筛选、事件详情和 JSONL 导出。
- 设置页集中提供自启、节点巡检间隔、并发数和失败阈值。
- 已检查 `/nodes`、`/workspace`、`/runtime`、`/log`、`/setting` 的桌面与移动布局。

### 3.2 代理池自动启动

- 新增持久化设置 `RuntimeAutoStartEnabled`，默认关闭，由管理员显式启用。
- 服务启动完成后按设置自动启动当前运行配置。
- 自动启动失败会写入结构化事件，不阻止 Web 控制面启动。
- 无可运行节点时停止 Mihomo；节点恢复后，仅在系统此前因健康原因停止时自动恢复。
- 用户手动停止具有最高优先级，后续健康恢复不会违背手动停止意图。

### 3.3 节点健康治理与故障切换

- 后台节点巡检默认开启，默认间隔 300 秒、并发 2、连续失败阈值 2。
- 启动后的首次自动巡检最多等待 10 秒；设置关闭时不会执行探测。
- 节点记录最近状态、延迟、错误、连续成功/失败次数和隔离时间。
- 连续失败达到阈值后节点进入隔离，并从新生成的运行配置中剔除。
- 探测成功后节点自动解除隔离、重新加入运行配置并触发 Mihomo 重载或恢复启动。
- 全量巡检端点纳入昂贵操作并发闸门，避免并发探测压垮主机。
- 健康结果采用字段级更新，避免覆盖并发编辑，也不会复活已删除节点。
- 端口配置保留用户指定的节点顺序，配置预览与实际渲染使用同一节点集合。

### 3.4 结构化且有界的日志

- 应用事件包含分类、级别、事件名、来源、消息和结构化详情。
- UI 按级别、分类、来源和关键词筛选，不再只展示难以扫描的原始文本。
- 支持导出 JSONL，便于后续分析和归档。
- 数据库日志最多保留 5000 条且最多 30 天，并执行小批量清理。
- `common.log` 与 `error.log` 分别按 4 MiB 轮转，各保留 2 个备份。
- 日志文件使用 `0600` 权限，避免同机非授权用户直接读取。

### 3.5 必要可靠性修复

- 删除节点时事务清理端口关系和运行快照，避免孤儿引用。
- 禁用与隔离节点不会进入新的 Mihomo 配置。
- 节点列表不再加载或返回敏感 `metadata_json`。
- 静态资源绕过 Web 页面限流，API 限流保持有效。
- 全量健康检查纳入昂贵操作限流。
- 运行配置预览的节点 ID 与实际渲染结果保持一致。
- 日志轮转、权限、保留策略和关键并发路径均补充回归测试。

## 5. 已知限制

- 当前无分页列表以 1000 个节点为 MVP 上限；更大规模需要游标加载和虚拟化。
- 健康探测使用管理员配置的单一测试 URL；连续失败阈值能降低瞬时误判，但尚无多目标或探测站故障保护。
- 故障切换发生在 Mihomo 的连接选择层，不等于应用层请求重放。
- 自动启动默认关闭，升级后需要管理员在设置页启用一次。
- 当前日志为结构化查询与有界持久化，不包含 SSE 实时事件总线、错误指纹聚合或远程日志后端。
